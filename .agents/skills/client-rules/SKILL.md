# Архитектура Frontend (Client)

**ОБЛАСТЬ ДЕЙСТВИЯ:** Эти правила применяются ТОЛЬКО к файлам внутри директории `apps/client/`. Если ты редактируешь сервер или парсеры, ИГНОРИРУЙ этот файл.

Ты работаешь в проекте со строгой слоевой архитектурой.
При создании или изменении файлов ты ОБЯЗАТЕЛЬНО должен соблюдать однонаправленный поток зависимостей.

## ГЛАВНОЕ ПРАВИЛО ИМПОРТОВ

Слой может импортировать ТОЛЬКО из слоев с меньшим числовым префиксом. Импорты "вверх" ЗАПРЕЩЕНЫ. Фичи не могут импортировать другие фичи.

## Слои в директории `components/`

- **`01.kit` (UI Kit)**: Атомарные компоненты.
  - _Правило для ИИ:_ НИКАКОГО стейта (Pinia), НИКАКИХ API-запросов. Только props и emits. Не импортируют ничего из других слоев.
- **`02.shared` (Виджеты)**: Общие блоки (например, хедер).
  - _Правило для ИИ:_ Могут использовать только компоненты из `01.kit`.
- **`03.domain` (Бизнес-сущности) / `04.features` (Фичи)**: (Если используются в проекте) Более сложная логика и изолированные срезы.
- **`05.modules` (Страницы/Блоки)**: Композиционный слой.
  - _Правило для ИИ:_ Здесь мы собираем виджеты и фичи вместе. Могут импортировать слои `01`–`04`.
- **`06.layouts`**: Шаблоны страниц.

## Внешние директории (Важно)

- **`pages/`**: Файлы здесь предназначены для роутинга. Они должны быть максимально тонкими и просто отображать содержимое из слоя `05.modules` или `06.layouts`.
- **`shared/`**: Содержит композиты (`composables`), константы (`constants`), сервисы (`services`) и глобальные сторы (`store`). Работа с API и файловым хранилищем (IndexedDB) должна быть инкапсулирована в сервисах или композитах здесь.

## Среда (Web / PWA)
- Приложение собирается только как Web / PWA, нативных платформ нет.
- Для работы с хранилищем используй абстракции из `shared/services` (например, `fs.client.ts` поверх IndexedDB).

## Инструкция по самопроверке для ИИ

Перед тем как сгенерировать код и сохранить файл, мысленно проверь:
1. Не нарушаю ли я правило префиксов `01-06` в секции `<script setup>` при импортах?
2. **НЕ ПЛОДИ ДУБЛИ:** Перед тем как создавать новый UI-компонент, ОБЯЗАТЕЛЬНО прочитай содержимое папки `components/01.kit` и `components/02.shared`. Если там уже есть подходящий компонент, используй его.

## Документация (MCP)
При работе с этим клиентским приложением, если ты не уверен в синтаксисе Vue 3, Pinia или VueUse, ОБЯЗАТЕЛЬНО используй инструменты из MCP-сервера `vue-docs`.

# Технический стек и Стилизация

1. **Стили:** Мы используем [SCSS / Vue style scoped]. НИКОГДА не пиши инлайн-стили (`style="..."`).
2. **Иконки:** Для иконок мы используем `import { Icon } from '@iconify/vue'` или локально сгенерированные иконки.
3. **Язык:** Всегда используй TypeScript (`<script setup lang="ts">`).
